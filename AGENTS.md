# AGENTS.md – working rules for Læsehjælper

Rules for AI coding agents (Claude Code, Codex, Cursor, …) and humans alike. `CONTRIBUTING.md` covers the human side (roadmap, issues, who merges); this file is how the work is done.

## The project in one paragraph

Læsehjælper is a browser app (PWA, GitHub Pages) that turns a photo of a children's book page into an easier-to-read page: OCR (Tesseract.js), page detection and dewarping (OpenCV.js), the old text painted over and re-set in a legible font with syllable colours, read-aloud, bookshelf (IndexedDB) and EPUB export. Everything runs on the user's device. Primary language Danish; also German and English, for books and UI.

## Non-negotiable rules

1. **Test-driven development.** For every change in behaviour: write the test first, run it and see it fail for the right reason (red), write the smallest code that makes it pass (green), then clean up (refactor) with all tests green. Bug fixes start with a test that reproduces the bug.
2. **TypeScript only**, strict mode. No `.js` source files anywhere in the repository (build scripts and configs too).
3. **One story or bug per pull request**, against `main`, with `Closes #<n>` in the description. Never push to `main`, never merge – only the maintainer (@eikrad) merges.
4. **Check library documentation with Context7 whenever it makes sense** – before using an API you have not used in this project yet, when upgrading a dependency, and when something behaves unexpectedly (`resolve-library-id`, then `query-docs`). Also run `npm outdated` when touching dependencies. Do not rely on memory for library APIs.
5. **Privacy:** no servers, no tracking, no uploads. Photos and books stay on the device.
6. **No copyrighted material** in the repository – no photos or text from real books, not even as fixtures. Test pages are self-made (see `tests/fixtures/`); real test photos live only in the git-ignored `private-testbilder/`.

## How to test

| What | Where | Tool |
|---|---|---|
| Pure logic (layout, syllables, word parts, geometry, EPUB, …) | small modules in `src/*.ts` | Vitest, `tests/unit/*.test.ts` |
| Everything the user does in the browser | `src/app.ts` and the page | Playwright, `tests/e2e/*.spec.ts` (import `test`/`expect` from `./fixtures`) |

- Put new logic into a small, pure module with unit tests; keep `src/app.ts` as thin glue that is covered by end-to-end tests.
- End-to-end tests that need speech output use a fake `speechSynthesis` (see `tests/e2e/start.spec.ts`).
- New fixture images are generated by a script from self-made content (HTML rendered with Playwright), never taken from books.

Node: CI runs on the current Node LTS (26); the minimum for local work is Node 22.15 (`engines` in `package.json`).

**Dependencies and security:** `npm audit` runs in CI and fails on moderate or worse. Dependabot opens weekly pull requests for npm packages and GitHub Actions. GitHub Actions are pinned to commit SHAs (with the version in a comment) so a hijacked tag cannot change what runs; when updating, take the SHA of the release tag. Check major updates with Context7 and the release notes before merging.

```bash
npm run lint           # Biome for source, tests and configuration
npm run typecheck      # TypeScript, strict
npm test               # unit tests
npm run build          # app into dist/
npm run test:e2e       # end-to-end tests (needs dist/)
npm run coverage       # unit + e2e coverage, merged, with minimum thresholds
```

**Coverage:** `npm run coverage` merges unit and browser coverage (Monocart, V8) and fails below the minimums in `coverage.ts` (lines 88 %, branches 76 %, functions 90 % as of November 2026). CI runs it on every pull request; the HTML report is attached to the run as the `coverage` artifact. Raise the minimums when coverage goes up; never lower them to make a pull request pass.

## Conventions

- **Languages:** every UI string exists in Danish, German and English (`T` in `src/app.ts`). The three READMEs (`README.md` Danish, `README.de.md`, `README.en.md`) are updated together.
- **Reading-support features are evidence-based.** Cite the study (author, year, DOI) in a code comment and in the README section “What does the research say?”. Features without clear evidence are optional and switched off by default.
- **Book quirks are settings, not defaults** (e.g. hyphenated syllables in some readers).
- **Commits:** English, imperative, explain why; end with `Closes #<n>` where it applies.
- **Stacked pull requests:** if several open pull requests touch the same lines (the translation table often does), branch from the previous one and say “builds on #…, merge in order” in the description.
- **Licences:** new third-party code or data goes into `THIRD_PARTY_NOTICES.md`; the project is MIT.

## Layout of the code

```
src/app.ts         UI glue: settings, pages, OCR queue, rendering, read-aloud, export
src/layout.ts      OCR words → paragraphs, cleaning, bold markers
src/silben.ts      syllables (TeX hyphenation patterns)
src/morpheme.ts    Danish word parts (word list from Stavekontrolden)
src/pagedetect.ts  page detection and dewarping (OpenCV.js)
src/prep.ts        image preparation (background flattening, rotation)
src/fit.ts, bold.ts, place.ts, lines.ts, spacing.ts, readflow.ts, profiles.ts, together.ts   small pure helpers
src/epub.ts, db.ts EPUB export/import, IndexedDB
build.ts           bundles everything into dist/ (esbuild)
```
